# Explainer channel

Faceless, AI-produced long-form tech-concept explainers, 6 to 8 minutes by default; a longer target needs a written reason in the brief (ep01 8:22, ep02 7:38). One folder per episode under `episodes/`: `<ep>` in the skills is that folder's name (`ep03-passkeys`), `<id>` the short Remotion composition id (`ep03`). The brief names the episode's **format**; format-dependent rules follow from it (`script-writing` §1).

## Pipeline (each step has a skill in `.claude/skills/`)

| # | Step | Skill | Output in `episodes/<ep>/` |
|---|------|-------|----------------------------|
| 1 | Research | `episode-research` | `factsheet.md` |
| 2 | Brief + art direction | `episode-brief`, `art-direction` | `brief.md`; a new look also writes `.claude/skills/art-direction/references/directions/<name>.md` |
| 3 | Script | `script-writing` | `script.md` |
| 4 | Script review (gate) | `script-review` | `reviews/script-*.md` |
| 5 | Storyboard + sound plan | `storyboard`, `sound-design` (plan) | `storyboard.md`, `storyboard.json`, the sound plan |
| 6 | Voice | `voice-narration` | `voice/` (wav + manifest) |
| 7 | Build, mix + render | `video-build`, `sound-design` (mix) | `out/<ep>.mp4` |
| 8 | Video QA (gate) | `video-qa` | `reviews/video-qa-*.md` |
| 9 | Packaging review | `package-review` | `reviews/package-*.md` |
| 10 | After publishing | `package-review` §3 | 24 h and 7 d numbers in `LEARNINGS.md` |

Gates: do not storyboard an unreviewed script, or from a brief marked "look not locked" (`episode-brief` §3); do not publish a video that fails `video-qa`. A check that could not run is NOT CHECKED, and NOT CHECKED is never a pass.
Done means: each step's output exists and, for a gate, its latest review says PASS. The episode is done at `episodes/<ep>/out/<ep>.mp4` with a PASS `video-qa` and `package-review` report. Delivery to the operator (Slack, upload) is the operator's own session: stop at the file and write `episodes/<ep>/HANDOFF.md` (what was made, gate verdicts with report paths, anything open). Stopping earlier, or at a step that waits for the operator (the act-1 pilot), write the same note and stop.

## Sources of truth (read before working)
- `LEARNINGS.md`: every "Operator feedback" section binds and overrides older text; the rest is history and lessons. Its first section lists withdrawn rules; an earlier episode's files are examples of form, never a source of rules (`episode-brief` §1).
- Reference studies: `docs/research/` (playbook, script-flow teardown, creative process, Manley/House). The per-video studies the skills cite under `research/` (each stating its type of video and the format its lessons are evidence for) are not in this repo.
- Measured targets: `docs/reference-baseline.md` (ranges from reference explainers; `video-qa` gates on them).
- Narration voice: `docs/my-writing-style.md` (sections 5 and 6 are binding for scripts).
- Every on-screen or spoken fact must trace to a VERIFIED line in the episode's `factsheet.md`.

## Tools
- Voice: ElevenLabs by default, `tools/tts/synth_elevenlabs.py`; Kokoro ONNX (`tools/tts/.venv/bin/python tools/tts/synth.py`, voice `af_heart`) is the offline fallback. How to use each: `voice-narration`.
- STT/QA: `tools/tts/.venv/bin/python tools/tts/transcribe.py <wav> [--words out.json]`; word times re-keyed to the script with `python3 tools/tts/align-words.py episodes/<ep>` (not in repo).
- Measured QA (`video-qa` §1, Python stdlib plus ffmpeg): `tools/qa/static_holds.py` (stills and near-empty frames), `tools/qa/loudness.py` (EBU R128), `tools/qa/spoken_words.py` (transcript against script), `tools/qa/pace.py` (cuts, picture changes and voice pace, for the reference baseline), `tools/qa/ratchet.py` with `tools/qa/ratchet.json` (per-check channel best). Text size and on-screen reading: method in `tools/qa/text_size.md`. Each prints its usage with `-h`.
- Storyboard and build: `tools/storyboard-lines.ts`, `tools/sync-storyboard-vo.py`, `tools/merge-segments.py`, `tools/beat-frames.py`, `bun tools/build-episode.ts episodes/<ep> <id>`; each prints its usage in its first lines.
- Video: Remotion in `video/` (`bunx tsc --noEmit` from `video/`); full renders only through `tools/render.sh <id> <out.mp4>` (lock rules: `docs/ops.md` §4).
- Remote stills: the Boat scripts (`tools/boat/`, not in repo); without them, take stills locally (`video-build` §1), one at a time.
- Independent reviewers: `codex exec` (ChatGPT plan), `claude -p` and `opencode run`.

## Reviews
- A gate's review comes from a different model family than the author's: one reviewer per gate by default, a second only for `script-review` Accuracy. Routing, model names in files, usage limits and file hashes: `docs/ops.md`.

## Machine
- One 16 GB laptop shared with other sessions: one heavy process at a time, one full render per fix round, never a second render beside a first (`docs/ops.md` §4).

## Rules
- Text, numbers, code and diagrams are built in code (Remotion), never generated by an image model.
- Disk is tight on this machine: one shared `video/node_modules`, render to `episodes/<ep>/out/`, delete intermediate frames.
- Record every issue and lesson in `LEARNINGS.md` as it happens.
- Git: commit nothing unless the operator asks; other sessions edit this repo at the same time, so never stash, reset or revert files you did not change.
